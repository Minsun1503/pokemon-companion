## Evidence recorded on November 10, 2026

Backend lint, type checks and production build passed; 261 tests passed and one remained skipped. Frontend checks/build and five chat/animation tests passed. Native contract and coordination checks passed after the latest native build. The expanded identity fixture independently observes application effects and rejects changed automation IDs, names and roles before input in both WinForms and Electron; WinForms also verifies a changed nonempty description. Chromium's in-place DOM ID edits may retain the old accessibility ID, so the Electron ID/role scenarios replace the node and wait for accessibility to expose the changed evidence. Tests do not pretend to detect information the provider has not exposed.

The actual MCPB was unpacked to a different folder and launched with bundled Node/Electron. All six tools, all seven pets, native readiness, cursor reads, package/handshake/status versions and the bundled versioned guide passed. The cached marketplace PowerShell relay also passed live MCP checks; its optional network download path was not run. App runtime version 0.1.0 and source marketplace wrapper version 0.1.1 are distinct. The launcher now reads an explicit runtime descriptor, and the marketplace check compares it with the app manifest and Claude download URL. Imported component manifests retain upstream versions in source; packaging stamps the app release version into the bundled backend manifest and lockfile.

At the user's request, Windows batch execution is now the default mode. The MCP schema supplies `action:"batch"` when omitted, and guidance groups known discovery/action/verification steps. Explicit atomic calls remain available for decisions between observations. MCP tests cover default and explicit modes, and missing/malformed plans are rejected before dispatch.

Electron on Windows uses OS profile paths independently of APPDATA overrides. Verification now supplies `POKEMON_USER_DATA_DIR` and confirms that the companion creates that separate profile. This isolates the tests' settings/chat/cache without claiming that concurrently launched production companions have automatic per-process profiles. Packaging and marketplace sources remain local; nothing was committed or uploaded.

The [dense discovery report](../benchmarks/results/scoped-discovery-2026-11-10.json) measures returned JSON characters for owned fixtures with 30 unrelated fields: 40 to one controls in WinForms, and 39 to one in Electron, with about 92% less context. It does not measure agent tokens or execution speed.

The [initial dense identity report](../benchmarks/results/identity-proof-2026-11-10.json) measured a warm native SetValue median of 5.01 ms for the starting worker and 324.28 ms with uniqueness checks. The [fresh-cache report](../benchmarks/results/identity-cache-2026-11-10.json) measured 4.93 ms and 307.75 ms respectively, with 16 independently verified edits and production artifact hashes. Identity now compares name and value from the same fresh cache; the modest difference between runs is insufficient to claim an optimization speedup. Full live uniqueness traversal remains a material latency cost. No cross-engine benchmark was run.

## Source-grounded outstanding decisions

- The reference [anchor resolver](https://github.com/vercel-labs/agent-desktop/blob/b43ac4f6/crates/windows/src/tree/resolve/resolve_anchor.rs) uses bounded path descent; its comments assign identity and completeness checks to core. Adopting cheap descent alone would remove our live uniqueness guarantee. Optimization must retain corroboration and incomplete-scan rejection.
- Reference [display enumeration](https://github.com/vercel-labs/agent-desktop/blob/b43ac4f6/crates/windows/src/system/display.rs) explicitly records single-display evidence and leaves multi-monitor validation open. Its fingerprinted capture design is relevant, but source inspection cannot establish multi-monitor reliability for either project.
- Reference [Action Center sessions](https://github.com/vercel-labs/agent-desktop/blob/b43ac4f6/crates/windows/src/notifications/session.rs) and [notification policy](https://github.com/vercel-labs/agent-desktop/blob/b43ac4f6/crates/core/src/commands/notification_policy.rs) distinguish adopting an already-open surface from raising and cleaning up a new one. Pokémon Companion currently exposes application windows only. Shell adoption requires that lifecycle and explicit focus policy; it is deferred while the higher-priority execution layer is verified.
- Reference [platform installation requirements](https://github.com/vercel-labs/agent-desktop/blob/b43ac4f6/docs/install.md) separate macOS Accessibility/Screen Recording/Automation permissions and Linux accessibility-bus/input dependencies. A generic adapter or an empty app list cannot establish permission or readiness on another OS. No non-Windows native claim is made.
- The current Electron clipboard backup preserves text, HTML, RTF and image, and restores when the current text equals the pasted text. It lacks a native change counter and arbitrary-format preservation. Another writer can copy identical text with different formats, so text equality cannot prove ownership. Cross-process mutual exclusion between companion servers does not resolve this race with the human or other apps.

Before opening this PR, the work was rebased onto main at `ccfd4b5`. Existing optional platform-bridge/ref support, clipped-value rejection and logical Chromium wrapper traversal were retained. Capture and live resolution share that traversal, keep root/sibling tracking independent of logical depth and bound raw ancestry to 80 levels. Native identity, boundary and cross-process checks passed after integration; 261 backend tests passed with one skipped.
