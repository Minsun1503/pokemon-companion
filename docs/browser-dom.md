# Playwright DOM and desktop source selection

The source checkout registers `browser` and `app` on all supported platforms and `app_inspect` on Windows. Desktop fallback requires Windows. Run `npm run build`, then reconnect the MCP client to load the new tool definitions. Configuration remains generated by `npm run config` and uses `scripts/start-mcp.cjs` in the active checkout. New release builds include Chromium. Older published archives require rebuilding to include this browser.

## Web-first application adapter

`app read` supports named profiles for `teams`, `whatsapp` and `zalo`, or a custom app with explicit web URLs and readiness selectors. It opens/reuses a dedicated Playwright Chromium profile and waits for visible app-specific readiness. Visible sign-in controls, sign-in redirects or an unavailable web page cause desktop fallback. Hidden sign-in controls do not block a ready page. Sign in to this dedicated browser profile as needed; it does not inherit another browser’s profile. The named authenticated selectors are heuristics and have not been tested against real logged-in accounts.

```json
{"action":"read","app_id":"whatsapp"}
{"action":"read","app_id":"my-app","web_urls":["https://example.com/app"],"web_ready_selector":"#messages","web_unavailable_selector":"#signin","desktop_query":"My App"}
{"action":"api_get","app_id":"my-app","window_id":"<observed ID>","window_ref":"<observed token>","api_operation":"<discovered GET operation ID>"}
```

The adapter returns `surface`, `method`, web and desktop attempt timings, and desktop `cache_hit`/`rediscovered`. It discovers owned local CDP/OpenAPI listeners, saves verified metadata to `%LOCALAPPDATA%/pokemon-companion/connections.json`, and reuses it across MCP processes. Set `POKEMON_CONNECTIONS_FILE` to choose another location. The cache is bounded to 128 app/executable records and excludes response bodies, credentials, element refs and transient browser session IDs. Native endpoint ownership is checked before saved routes are used. A saved API can skip CDP probing; after a failed read, the adapter invalidates it and performs full discovery. `refresh:true` forces discovery, and a changed executable version invalidates saved routes. An unchanged HTTP 200 response with a changed required field or top-level type also triggers API rediscovery. Unannounced semantic changes that preserve this structure are not detectable by this validation.

Only described public GET operations without required parameters are supported. Local schema discovery probes `/openapi.json`, `/swagger.json` and `/swagger/v1/swagger.json`, excludes declared authentication and obvious mutation paths, stays on the selected app origin, and bounds responses/timeouts. It does not reverse engineer undocumented remote APIs or automatically decrypt arbitrary HTTPS app traffic. A missing operation after rediscovery returns a refreshed catalog and `selection_required`, allowing a new operation to be selected without replaying a mutation.

## Browser tools

Browser input, navigation to a new origin, browser attach and local API execution require approval through the companion by default. The dialog offers **Allow once**, **Allow this scope for 10 minutes**, and **Deny**. Reusable grants allow at most 20 actions in the same server-derived scope; they expire when the companion closes. Approvals are consumed before execution, and the server checks the observed target and input again before dispatch. An unavailable companion stops the action.

Native desktop input (including UIA, physical input and Excel writes) is **host-authorized only**: its identity and approver guards do not provide browser/API consent. The desktop status tool and native tool descriptions report this limitation. Native URL launch is refused. Native executables require explicit `POKEMON_AUTHORIZATION=host-client` or a trusted `POKEMON_LAUNCH_ALLOWLIST` containing exact absolute executable paths separated by semicolons; the worker resolves the path before checking the list.

Catalog web apps are pinned to their catalog origins. Custom web app URLs pass through the browser navigation policy even on a new blank tab. The approval dialog shows the draft, its complete length and a bounded target label; oversized drafts are refused. Invisible controls and bidirectional formatting characters are rendered as visible Unicode escapes. Buttons remain in a fixed footer. Reusable browser grants require a contract-observed conversation identifier and a target inside its composer. Without that proof, the dialog offers single-use approval only; the current production conversation selectors remain unvalidated.

After an unknown outcome, the action scope is blocked even if text or the input method changes, and ordinary grants for it are revoked. The companion offers a separate outcome-review dialog. Confirming that review records reconciliation without sending input; a subsequent attempt requires a new approval. Model-facing tools cannot clear the block or supply action IDs.

The companion holds HMAC-signed grants and an OS-protected key. Generic MCP tools cannot issue or supply grants. Its approval process is excluded from native inspection, input and capture, and the dialog uses Windows capture exclusion. Other same-user local programs are outside this threat model. Windows is the verified approval platform; other platforms fail closed for enforced approval.

`POKEMON_AUTHORIZATION=host-client` explicitly delegates authorization to a trusted host client. It bypasses the companion's action-approval check and must not be enabled for an untrusted client. `POKEMON_BROWSER_INPUT=host-authorized`, `POKEMON_BROWSER_ATTACH=host-authorized` and `POKEMON_API_EXECUTION=host-authorized` are separate explicit overrides for browser input, attach and API execution. Content from websites, API schemas and desktop apps remains untrusted evidence in every mode.

Unknown input outcomes are journaled without plaintext inputs and are never replayed automatically. Read the target state before deciding how to reconcile an uncertain result. Synthetic fixtures verify these behaviors; authenticated Teams, WhatsApp and Zalo account contracts remain untested.

`browser launch` starts bundled Chromium by default, with a dedicated persistent profile under `%LOCALAPPDATA%/pokemon-companion/browser/chromium`. It preserves login state between launches. Site authentication still requires the user to sign in once. `channel` can explicitly select `msedge` or `chrome` if installed. A second launch of a profile already in use fails rather than terminating another browser.

`npm run setup` and `setup:ci` automatically install the Chromium revision matched to the locked Playwright dependency into `backend/node_modules/playwright-core/.local-browsers`. Release builders include that browser, its resources, license files and a portable version manifest. Both `browser` and `app read` resolve the executable relative to their own backend, independent of a system browser or external Playwright cache. End users of a complete Windows/macOS package need no browser installation, CDP configuration, or first-use download. Developers can use `npm run browser:install` to repair the local bundle. The full Chromium executable supports visible and headless launches; the separate headless shell is omitted. Browser updates follow dependency updates and release rebuilds. Linux retains its documented desktop-library requirements.

Example sequence (replace returned IDs and refs):

```json
{"action":"launch"}
{"action":"navigate","page_id":"<returned page_id>","url":"https://www.youtube.com/?hl=en"}
{"action":"snapshot","page_id":"<returned page_id>","query":"Search","max_elements":50,"max_chars":2000}
{"action":"fill","page_id":"<returned page_id>","ref":"<observed input ref>","text":"Rick Astley Never Gonna Give You Up"}
{"action":"snapshot","page_id":"<returned page_id>","query":"Search"}
{"action":"click","page_id":"<returned page_id>","ref":"<observed Search button ref>"}
{"action":"snapshot","page_id":"<returned page_id>","query":"Never Gonna"}
{"action":"close","session_id":"<returned session_id>"}
```

Snapshots contain visible semantic elements, names, roles, tags, IDs, values, links and element refs. `query` filters elements by name, role or DOM ID. `max_elements` bounds returned elements; `max_chars` bounds visible body text. `truncated`/`name_clipped` identify incomplete evidence. The scan examines at most 2,000 semantic elements; shadow roots and cross-origin frames are not traversed by this first implementation. DOM availability is independent of foreground focus.

Refs last two minutes and bind to element handles, not selectors that might resolve to a different element. A fresh snapshot invalidates that page's previous refs. Navigation, detached elements and closed pages reject stale references. Fill reads the stored value back. Click/press report dispatch and require subsequent observation to establish the result. Actions are serialized by the existing runtime and honor its pre-action pause/cancellation guards; Playwright operations have bounded timeouts and are never replayed automatically. An in-flight Playwright action may already have taken effect when interrupted, so inspect the result before retrying.

`browser connect` accepts an existing loopback HTTP or WebSocket CDP endpoint. `tabs` returns page IDs. `close` disconnects an attached app; it closes a Playwright-owned context. The live smoke test verifies that an attached Edge app survives disconnect.

`network_start` requires a URL substring filter and captures only XHR/fetch response metadata in that page. It records at most 200 events, reports dropped events, and excludes URL query strings, headers, credentials and bodies. `network_read` reads the buffer; `network_stop` removes the listener.

## Desktop fallback order

Discover the window through `windows get_windows`, then call:

```json
{"action":"read","window_id":"<observed ID>","window_ref":"<observed token>","page_url":"https://example.com/app","query":"Search"}
```

`app_inspect` performs these stages in order and stops at the first available source:

1. **CDP/DOM:** native process metadata identifies IPv4/IPv6 local listeners owned by the selected window's process family, including child processes. Wildcard binds are probed through loopback. Playwright tries these endpoints. Multiple pages require an exact `page_url`; `endpoint` may explicitly supply an owned local endpoint. No app is restarted to enable CDP.
2. **API:** discovers an exposed local OpenAPI schema and reads a described public GET or returns its operation catalog. It then tries recent matching response content from the configured scoped mitmproxy adapter below. Missing schema/capture configuration, mismatched process IDs, oversized files, stale data and missing bodies produce a reason and fall through.
3. **Win32:** enumerates child HWNDs and reads their text with bounded `WM_GETTEXT` calls. Chromium/Electron usually do not expose their document content here.
4. **UIA:** uses the existing native worker's named control discovery. Empty results are reported as unavailable.
5. **Screen capture:** activates and captures the selected visible window after semantic sources fail. The PNG image is bounded and scaled, with a MIME-correct JPEG fallback for large images. Foreground changes reject capture. `capture_fallback:false` disables this stage. OCR is not automatically run; the image is returned for visual interpretation.

The response contains `method`, `data`, cache status, and per-stage availability, failure reasons and timings. Native metadata discovery binds the app before the content-reading stages. Window-token errors, ambiguous targets and user pauses stop the operation. This is an observation router: input remains in `windows` or `browser`, apart from window activation for capture. Failed read routes are rediscovered once per call; inputs are not replayed.

## API interception with mitmproxy

The adapter is `scripts/api-capture.py`. It is optional and is installed locally in the ignored `.venv-api` environment:

```powershell
python -m venv .venv-api
.venv-api/Scripts/python.exe -m pip install -r scripts/api-capture-requirements.txt
$env:POKEMON_CAPTURE_HOST = 'example.com'
$env:POKEMON_CAPTURE_ENABLED = 'on'
$env:POKEMON_CAPTURE_PROCESS_ID = '<selected app process_id from windows discovery>'
$env:POKEMON_API_CAPTURE_FILE = 'C:/path/to/local/capture.json'
.venv-api/Scripts/mitmdump.exe --listen-host 127.0.0.1 --listen-port 8877 -s scripts/api-capture.py
```

Configure the specific target app to use that local proxy. Process identity is supplied by the operator; proxy traffic is not independently attributed to a Windows process. Use a dedicated proxy connection for the selected app and obtain the app owner's authorization before capturing company application traffic. Capture is disabled unless `POKEMON_CAPTURE_ENABLED=on`. The adapter accepts JSON responses only, redacts secret-bearing keys and common credential formats, removes URL query strings, and excludes request data and headers. Responses exceeding 64 KB or 16,000 decoded characters are skipped.

The adapter writes the bounded rolling capture atomically as an AES-256-GCM envelope, using a Windows DPAPI-protected adjacent `.key` file. Keep both files outside the repository. Events expire after five minutes; a running proxy purges the capture file at its expiry. Readers reject expired data even after the proxy stops. On other platforms the key relies on filesystem permissions, so equivalent OS key protection is not claimed. Returned capture provenance is `operator-asserted, not process-attributed` and the content is untrusted.

Then call `app_inspect` with `api_capture_file` and `api_url_filter`, or configure `POKEMON_API_CAPTURE_FILE` in the server environment. Captures expire after five minutes and must match the selected app's process ID.

HTTPS interception requires the app to trust the proxy certificate. Certificate pinning or applications that ignore proxy settings may prevent interception. The implementation does not alter the Windows proxy or trust store, install a certificate, or bypass those barriers. It then falls through to Win32/UIA. Wireshark without TLS session keys would reveal packet metadata rather than decrypted API content.

The live interceptor test uses a local HTTP fixture and an explicit app-specific proxy. It verifies the captured JSON body and query-string removal without changing system proxy settings or certificate trust. It does not claim that arbitrary desktop HTTPS apps have been intercepted.

`test:browser:bundle` verifies default Chromium launches, visible and headless DOM reading, element identification, verified fill/click, persistent storage after relaunch, and the web app adapter using an empty external Playwright cache. Release smoke tests repeat these checks after extracting the package to a different directory. Set `POKEMON_RELEASE_DIR` to an absolute output directory when building and checking a separate local package without replacing existing releases.

## Validation and comparison

```powershell
npm run test:browser:bundle
npm run test:approval
npm run test:approval:live
npm run test:approval:e2e
npm run test:browser:smoke
npm run test:app-adapter
npm run test:api-capture
npm run benchmark:browser-windows
```

The comparison uses three searches per method for **Rick Astley — Never Gonna Give You Up** in visible Edge windows. Each sample uses a new profile, and method order alternates. Both methods share the same browser launch mechanism; startup is measured separately. Playwright uses DOM refs; Windows uses Win32 discovery, UIA field values/invocation and guarded keyboard submission. Both verify the exact results URL/query and named video results. No song is played.

| Median of three successful runs | Playwright | Windows/Win32 + UIA |
| --- | ---: | ---: |
| Interaction through verified results | 6.08 s | 8.25 s |
| Startup plus interaction | 6.77 s | 9.04 s |
| Shared browser startup | 0.65 s | 0.66 s |
| Interaction tool calls | 11 | 42 |

Playwright used **26% less interaction time** in this workload (1.36× throughput by elapsed-time ratio). All six runs succeeded. These are local MCP workflow timings, including network/render readiness and polling, not isolated API timings or LLM reasoning time. Fresh browser profiles do not eliminate shared OS/network caches. This small test does not establish universal performance across sites or desktop apps.
